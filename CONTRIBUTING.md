# Contributing

Almagest is MIT-licensed. Fixes, new audit checks, harness support and docs
improvements are welcome. This file covers what you need to get a change in.

## Requirements

- Node.js 22 or later for the root package and `tools/audit.mjs`.
- Node.js 22.13 or later for `server/` (it uses the built-in `node:sqlite`),
  and git 2.38 or later (`merge-tree --write-tree`).
- A recent Node.js 22 for `site/`. Astro sets the floor, currently 22.23.4;
  `site/package.json` → `engines` records it.
- Bash and coreutils, for `tools/agent-shims.sh` and the benchmark harness.

## Setup

The root install also installs the `server` workspace:

```bash
npm install
```

The site has its own `package.json` and builds without the root install:

```bash
cd site && npm install
```

## Checks to run before a pull request

These are the checks CI runs (`.github/workflows/ci.yml`). Run them from the
repository root:

```bash
npm ci
tools/agent-shims.sh check
node tools/audit.mjs --check-index
node tools/audit.mjs
node tools/lib/selftest.mjs
npm test --workspace server
benchmarks/selftest.sh
(cd site && npm ci && npm run build)
```

`npm run check` runs the shim check, the index check and the audit in one go,
and `npm run selftest` and `npm run test:server` are aliases for the audit
selftest and the server tests. CI also runs an advisory job that flags direct commits to
`brain/wiki/` on `main`; it does not block anything.

## Invariants to keep

Almagest keeps each thing in exactly one place so that nothing can drift. A
change that breaks one of these will be asked to change.

- Rules live once, in `agent/rules/`. The per-harness files (`AGENTS.md`,
  `GEMINI.md`, `.github/copilot-instructions.md`, `.claude/rules/*`,
  `.cursor/rules/*`, `brain/CLAUDE.md`) are generated pointers from
  `tools/agent-shims.sh`. Never edit one by hand: change the source, run
  `tools/agent-shims.sh generate`, and let `tools/agent-shims.sh check` verify.
  A hand-edited copy drifts from the rules the agent is supposed to follow.
- `tools/lib/wiki-core.mjs` is the single wiki parser, shared by the audit and
  the site. It imports no packages (`gray-matter` and `marked` are injected)
  and stays `.mjs`. The site must build without the root install, and bare Node
  cannot import TypeScript.
- `brain/.index/` is generated by `node tools/audit.mjs index` and committed.
  Never edit it by hand.
- Audit check IDs (`CITE-002`, `LINK-001`, ...) are stable, and the rule files
  and docs refer to them. A new or changed check updates `docs/audit.md` and
  the selftest fixtures in `tools/lib/__fixtures__/` in the same change.
- `docs/v2/spec.md` is the contract between the service's modules. A change to
  a contract it defines changes that file in the same commit.
- A security-relevant change to `server/` comes with a regression test under
  `server/test/`.

## What will not be accepted

Anything that lets an agent approve a change or merge to `main` unattended.
Unattended ingest onto a branch is supported; the README says there is no flag
for an unattended merge, and there will not be one.

## Pull requests

- Branch off `main`, and keep one topic per pull request.
- CI must be green.
- Commit subjects in this repo are short, descriptive and in the imperative or
  plain past ("Refuse a GitHub merge commit whose tree is not the reviewed
  merge", "Add a reference-transaction hook as the backstop for moves of
  main"). Many carry an area prefix and a colon, such as `README:`, `Docs:`,
  `Site:` or `governance:`. Do not add "Generated with" lines or
  `Co-Authored-By` trailers.
- Do not commit to `brain/wiki/` on `main` and do not hand-resolve conflicts in
  generated files; take either side and regenerate (see
  [Upstream Updates](docs/upstream-updates.md)).

## Reporting vulnerabilities

Do not open an issue. Follow [SECURITY.md](SECURITY.md).
